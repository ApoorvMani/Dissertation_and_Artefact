How the final ASR is measured

The before/after ASR comparison uses the same defence-conditioned sample set. A sample enters the paired ASR calculation only when the clean toxic version remains toxic after the defence. This prevents defence-induced classifier damage from being incorrectly counted as an adversarial success.

For each retained sample:

clean + defence → toxic
then compare
attacked without defence against attacked + defence.

Data-derived findings

  • TokenBreak: lowest paired defended ASR = 46.5% (Tokenizer translation).
  • AdvTok: lowest paired defended ASR = 0.0% (Tokenizer translation, Canonical reject, Canonical replace, Unicode sanitiser, NFKC + confusables).
  • Unicode compatibility: lowest paired defended ASR = 0.0% (Tokenizer translation, NFKC + confusables).
  • Unicode homoglyph: lowest paired defended ASR = 0.0% (NFKC + confusables).
  • Unicode invisible: lowest paired defended ASR = 0.0% (Canonical reject, Canonical replace, Unicode sanitiser, NFKC + confusables, Global CPT, Window CPT).
  • Unicode reorder: lowest paired defended ASR = 0.0% (Unicode sanitiser).
  • Defence-induced regressions: Unicode invisible + Tokenizer translation (-13.4 pp).
  • AdvTok interface effect: Tokenizer translation, Unicode sanitiser, NFKC + confusables discarded supplied adversarial IDs through re-encoding rather than detecting the noncanonical tokenization.

Interpretation of the clean metrics

False alarm rate: clean input is flagged by the defence.

False block rate: clean input would actually be rejected by the deployment policy.

Baseline-decision preservation: the input is not blocked and the victim classifier gives the same decision it gave before adding the defence. This is deliberately different from the victim model's own toxicity false-positive rate.

Literature provenance

  • TokenBreak — Schulz, Yeung & Evans (2025). Tokenizer Translation is based on the paper's Unigram-to-original-tokenizer defence. arXiv:2506.07948
  • Adversarial Tokenization — Geh, Shao & Van den Broeck, ACL 2025. The paper motivates retokenisation and string-only interfaces as defences against noncanonical token sequences. ACL Anthology
  • Bad Characters — Boucher et al. Provides the Unicode adversarial-input motivation behind the sanitisation family. arXiv:2106.09898
  • Unicode UTS #39 — used as the standards basis for confusable-character detection. Unicode Security Mechanisms
  • Broken-Token — Zychlinski & Kainan. Provides global and sliding-window CPT filtering. The WordPiece calibration strategy used in this dissertation is explicitly an adaptation rather than an exact reproduction. arXiv:2510.26847
  • Bootstrap uncertainty — Efron (1979), Bootstrap Methods: Another Look at the Jackknife. The analysis uses paired percentile bootstrap confidence intervals.

Important interpretation warning

A low defended ASR does not automatically mean that the named defence detected the attack. For AdvTok in particular, reencode = 100% means the attacker-supplied token IDs were discarded because the defence reconstructed input from the visible string. That is an interface effect, not attack detection. The detection-rate and re-encoding plots must therefore be read alongside the defended-ASR plot.

Scope

These results currently establish the main experiment for one WordPiece toxicity classifier. They do not yet establish cross-tokenizer or cross-model generality. Those are separate experiments.
